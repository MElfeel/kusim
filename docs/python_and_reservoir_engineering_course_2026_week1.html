Welcome

This week you will learn the first steps of Python and, at the same time, the most important idea in reservoir simulation: a model is a simplification, and a numerical model takes small time steps. You need some calculus and linear algebra, but no programming experience. Nothing here needs a spreadsheet, and you do not need to know any reservoir simulation.

The shape of one study day (about 1 hour)
  • Story (5 min): a short subsurface anecdote that explains why today's topic matters.
  • Concept and by-hand step (15 min): a few steps calculated on paper, then confirmed in code.
  • Guided coding (25 min): short exercises, each with a check cell and a hidden solution.
  • Predict, then run (5 min): guess first, change one number, compare.
  • Quiz and bridge (10 min): a self-quiz, and the same idea inside kusim, the real reservoir simulator you will use in later weeks.
Every Python idea follows see it, predict it, do it. Weekends are free for catching up.

By the end of Week 1 you will be able to

  • run and edit a Jupyter notebook, use variables, numbers, strings, lists and for / while loops,
  • make decisions with if / elif / else and package a calculation as a function,
  • read a Python error message and find the line that caused it,
  • solve a simple growth model both exactly and numerically, plot both, and see how the time step controls the error,
  • recognise when a time step that is too large makes the answer oscillate (numerical instability),
  • calculate bulk volume, pore volume and original oil in place (OOIP) in oilfield units,
  • read a PVT table from a file and write your own linear-interpolation function, the one every simulator uses to read tables.

A closer look at each day

Day 1: What is a simulation model? (and your first Python)

The story is a forecast that was "right" for three years and then failed. You build a model of a growing colony, solve it exactly, then step through it numerically by hand, then in a for loop. Plotting both curves shows the gap, and shrinking the time step shows the gap closing. The day ends with the question that runs through the whole course: is this model fit for purpose?

Day 2: Making decisions and writing functions

A well is shut in by a rule, and you write that rule in code. You learn why 0.1 + 0.2 == 0.3 is False, the difference between print and return, and how try/except protects a calculation from bad input. Then you wrap the Day 1 model in a function and call it for many time steps.

Day 3: Repeating until something happens

How long until the economic limit is reached? A while loop answers it. You meet an infinite loop on purpose, then the logistic equation (growth limited by food, or by reservoir energy). When Δt is too large the numerical answer swings up and down, and you will see why. Stable is not the same as accurate.

Day 4: Reservoir volumes, units and text

A factor of 5.6 hides in every oilfield calculation (5.615 ft³ per barrel). You calculate OOIP, see what a forgotten factor does, and learn to turn text such as DX 100 75 50 75 100 into numbers, which is how simulator input files are read.

Day 5: Fluid property tables, files and your own interpolation

A PVT table that lived in an email. You write it to a file and read it back, treat it as a list of rows, and write linear interpolation yourself, including what to do outside the table. You then summarise a production log with a few bad lines. The last section is a Week 1 self-assessment.

Deliberate order difference. The book teaches lists late, but even the simplest time-stepping model must store its results, so lists and a first for loop appear on Day 1. Day 1 points you to a short preview of Chapter 8 for that reason.

Setup: before Day 1

Allow 30 to 45 minutes, mostly waiting for downloads, and an internet connection. You install three things; you do not install Python yourself, because uv does that for you in a private folder and changes nothing else on your computer.

ToolWhat it is for
TerminalA window where you type commands. Already on your computer.
gitDownloads the course and kusim from GitHub.
uvInstalls Python and every package kusim needs, in one private folder (.venv).
JupyterLabThe notebook program you work in every day. It is started through uv.

Type each command into the terminal and press Enter. Lines that start with # are comments for you to read; leave them out.

  1. Open a terminal

    Windows: press the Windows key, type PowerShell, open Windows PowerShell. macOS: Cmd + Space, type Terminal. Linux: open Terminal.

  2. Install git

    Check first:

    git --version

    If it prints a version (for example git version 2.45.0), go to step 3. Otherwise:

    • Windows: download Git for Windows from git-scm.com/download/win, run it and click Next through every page. Then close PowerShell and open a new window.
    • macOS: if a window offers to install the command line developer tools, click Install and wait.
    • Linux (Ubuntu/Debian): sudo apt install git

  3. Install uv

    Windows (PowerShell)
    powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
    macOS and Linux
    curl -LsSf https://astral.sh/uv/install.sh | sh

    Close the terminal and open a new one, then check:

    uv --version

    Any version number is fine.

  4. Download the course and kusim

    Pick a folder you can find again (this example uses Documents):

    cd Documents
git clone https://github.com/MElfeel/kusim.git
cd kusim

    From now on, every command is typed inside the kusim folder. In a new terminal, go back with cd Documents/kusim.

    Windows and OneDrive. If Documents is synced to OneDrive and you see odd errors later, use a folder outside it, for example cd C:\, then mkdir work, cd work, and run git clone there.

  5. Install Python and all the packages

    Inside the kusim folder:

    uv sync --extra dev

    This downloads Python 3.12 if you do not already have it (it ignores any other Python on your computer), creates the private .venv folder, and installs kusim with NumPy, SciPy, pandas, matplotlib, plotly and pytest, in the exact versions the course was written with. It takes a few minutes and prints a lot; that is normal. When your prompt comes back without a red error, it worked. There is nothing to "activate": put uv run in front of a command to run it in that environment.

  6. Start JupyterLab

    uv run --with jupyterlab jupyter lab

    A browser tab opens. If not, copy the line starting with http://localhost:8888/lab?token=... from the terminal into your browser. In the file list on the left open course, then day01, then double-click day01_simulation_models.ipynb.

    • Keep the terminal window open while you work (minimise it). It is the engine behind the notebook.
    • To stop: save with Ctrl+S, click in the terminal, press Ctrl+C (answer y if asked).

  7. Check that it all works

    In JupyterLab choose File, New, Notebook (kernel: Python 3), type this in the first cell and press Shift + Enter:

    import kusim, numpy, pandas, matplotlib
print("kusim version", kusim.__version__)

    You should see a line starting with kusim version. If you see ModuleNotFoundError, see the troubleshooting table below.

    Optional second check, in a second terminal inside the kusim folder:

    uv run kusim version
Done? Open day01_simulation_models.ipynb and start at "0. How a notebook works". You do not need any other preparation.

Each time you study

  1. Open a terminal and go to the folder: cd Documents/kusim
  2. (Only when the course team tells you there is an update) git pull, then uv sync --extra dev
  3. Start the notebooks: uv run --with jupyterlab jupyter lab
  4. When finished: Ctrl+S to save, Ctrl+C in the terminal to stop.

Your changes are saved in your own copy. Before git pull, duplicate any notebook you edited (right-click it in JupyterLab, Duplicate), because git pull can refuse to overwrite a changed notebook.

Habits that make Week 1 easier

  • Run the cells in order, top to bottom. If something behaves strangely, use Kernel, Restart Kernel and Run All Cells.
  • Predict before you run. Write your guess, then check it. It is the fastest way to learn.
  • Read the last line of an error first. It names the problem (NameError, IndexError, SyntaxError), and the line above points at where.
  • Type the examples instead of only reading them, and change one number to see what happens.
  • Use the weekends for catching up. Day 5 ends with a self-assessment of the whole week.

Troubleshooting

What you seeWhat to do
uv or git "is not recognized" / "command not found"Close the terminal and open a new one. If it still fails, repeat that install step.
PowerShell: "running scripts is disabled"Run Set-ExecutionPolicy -Scope CurrentUser RemoteSigned, answer Y, try again.
uv install or download fails with a certificate or network error (common on company or university networks)Try another network (a phone hotspot), or ask your IT office. Adding --native-tls often helps: uv sync --native-tls --extra dev.
git clone: "destination path 'kusim' already exists"You already downloaded it. Run cd kusim and continue at step 5.
uv sync cannot find pyproject.tomlYou are not inside the kusim folder. cd kusim and try again.
ModuleNotFoundError: No module named 'kusim' in a notebookJupyterLab was not started with uv run inside the kusim folder. Stop it (Ctrl+C), cd kusim, start it again exactly as in step 6.
The browser tab does not openCopy the http://localhost:8888/... address from the terminal into your browser.
"Port 8888 is already in use"JupyterLab is already running in another terminal. Use that one, or close it first.
I pasted several commands and one failedRun them one at a time and read the message after each. The last lines of an error usually say what is wrong.
Anything elseCopy the whole error message and the command that caused it, and send both to the course team.

What you installed, in one line each

  • git clone made a copy of the project in the kusim folder.
  • uv sync made the private .venv folder with Python and the packages in it.
  • uv run ... runs a command inside that private environment.
  • JupyterLab is the notebook program; each .ipynb file is a notebook.

To remove everything later, delete the kusim folder (and uninstall git and uv like any other program). Nothing else on your computer was changed.
